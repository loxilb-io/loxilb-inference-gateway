# LoxiLB Inference Gateway — Monitoring Stack (Prometheus + Grafana)

Operator monitoring for a loxilb-inference-gateway instance.

## Current coverage boundary

The shipped Prometheus configuration scrapes the Gateway and Prometheus itself. A Gateway
scrape collects every family that the running build and workload currently emit; it does not
select families one by one. The repository owns **196 possible Gateway families**, but the
current development-checkout target baseline is **163** after excluding 24 DPU/DOCA families,
8 Gateway-side AI-controller bridge families, and 1 Gateway-side KV-agent health family.
PII detection is also package-excluded, but adds no Prometheus family, so it does not change
those counts. The standalone AI controller (19 families) and KV agent (4 families) are
source-only and have no default scrape jobs.

This is not yet locked-RC coverage: ProductLock pins Gateway `f08b18b…`, whereas this inventory
and these monitoring assets are reviewed at `c83a24d…`. Nine current families are absent from
the locked revision, including four referenced by current dashboards/rules. Align ProductLock
to the verified Gateway revision or regenerate the inventory/assets at the locked revision
before using these figures as release evidence. Prometheus/Grafana are also not current
ProductLock runtime images; this repository stack is an implementation candidate pending
packaging and security approval.

The default dashboards and rules reference **95 / 163** applicable Gateway families,
leaving **68** applicable families unreferenced. The six former component-boundary references
(four `doca_*` Overview queries, the `loxilb_kv_agent_up` fallback and alert, and the
cross-exporter `aictrl_ttft_pred_err_ratio_p90` panel) have been removed, and the monitoring
lint gate now rejects any reintroduction — including as fallbacks inside a larger expression.
The committed metric ownership manifest (`deploy/monitoring/manifest/metric-manifest.json`,
regenerated by `deploy/monitoring/ci/gen-metric-manifest.py`) is the authoritative
per-family record of owner, applicability, activation behavior, and current consumers.

The optional `GET /config/pii/stats` JSON route is not a monitoring substitute: its current
handler returns fixed zero placeholders because aggregation is unimplemented. Do not surface
those values in Grafana or UI as observed PII activity.

## Quick start (default — same-host, network-isolated scrape)

Run this stack **on the loxilb host** and scrape the plain REST listener over localhost.
The default uses network isolation. This is distinct from both per-LB-rule data-path mTLS and
the API HTTPS listener's optional client-certificate verification.

```bash
cd deploy/monitoring

# 1. Grafana admin credentials
cp .env.example .env            # then edit the password

# 2. Keep loxilb's plain listener host-local (bind to localhost or firewall :11111).
#    prometheus.yml already targets 127.0.0.1:11111 over http.
docker compose up -d

# 3. Enable metrics collection (endpoint answers 503 until enabled)
curl -X POST http://127.0.0.1:11111/netlox/v1/config/metrics
```

- Prometheus: `http://<host>:9090` — Grafana: `http://<host>:3000` (credentials from `.env`).
- Dashboards are provisioned from `grafana/dashboards/` into the **LoxiLB** folder.

## Security notes

- **The metrics endpoint is intentionally unauthenticated.** The Swagger operation declares
  `security: []`, and its generated handler has no principal. Enabling `--userservice`,
  `--oauth2`, or manual-token auth does not add a bearer check to `/metrics`. Treat every
  listener that exposes this route as a telemetry disclosure boundary.
- **Default posture = network isolation.** Bind loxilb's plain listener to localhost
  (`--host 127.0.0.1`) or firewall `:11111`, and run Prometheus on the same host. No certs,
  no tokens. (On the cicd testbed `:11111` stays open on purpose — cicd scripts use it.)
- **Prometheus itself binds to loopback** (`--web.listen-address=127.0.0.1:9090` in the
  shipped compose file). Prometheus has no authentication of its own and proxies every metric
  it scraped; treat its API like the metrics endpoint. Grafana (authenticated, port 3000) is
  the intended remote-facing surface. To expose Prometheus beyond the host, front it with an
  authenticated proxy on the management network instead of widening the bind.
- If a site requires authenticated remote scraping, put an authenticated reverse proxy or
  service-mesh policy in front of the endpoint. Never assume the Gateway API bearer setting
  protects `/metrics`.

## Optional: transport encryption across a network

Only if you must scrape loxilb across an untrusted network. Server TLS encrypts the channel;
when `TLS_CA_CERTIFICATE`/`--tls-ca` is configured, the API HTTPS server uses
`RequireAndVerifyClientCert`, so a Prometheus client certificate is required and verified.
This transport-layer mTLS is separate from the operation's app-layer `security: []`.

```bash
# 1. Certs — SANs must cover the address Prometheus scrapes
./certs/gen-certs.sh <loxilb-ip> [more SANs...]

# 2. Install server cert + CA and (re)start loxilb with --tls
docker cp certs/server.crt llb1:/opt/loxilb/cert/server.crt
docker cp certs/server.key llb1:/opt/loxilb/cert/server.key
docker cp certs/rootCA.crt llb1:/opt/loxilb/cert/rootCA.crt
docker exec llb1 pkill loxilb
docker exec -dt -e TLS_CA_CERTIFICATE=/opt/loxilb/cert/rootCA.crt \
  llb1 /root/loxilb-io/loxilb/loxilb --tls
#    (--tls-ca is only on the API sub-parser; pass the CA via TLS_CA_CERTIFICATE.)

# 3. In docker-compose.yml uncomment the cert bind-mounts + `user: "0"`, and in
#    prometheus.yml switch to the commented https/:8091 block. Then:
docker compose up -d
```

- `certs/rootCA.key` signs everything — keep it out of images/repos (the certs dir is
  git-ignored except `gen-certs.sh`). Generate on a trusted host; distribute only leaf
  certs + `rootCA.crt`.

## Operational notes

- Scrape interval is 10 s to match loxilb's internal stats sweep — don't lower it.
- `up == 0` has two meanings: process/network down, or metrics collection disabled
  (HTTP 503). The `LoxilbScrapeDown` alert runbook covers both.
- `loxilb_active_conntrack_entries`, `loxilb_requests_total`, and per-client/per-endpoint
  counters are sweep-derived and may miss connections shorter than the 10 s sweep.
  `loxilb_processed_*` and `loxilb_service_traffic_*` are datapath accounting counters and
  include short-lived traffic; do not apply the conntrack sampling caveat to them.
- On the cicd testbed, many data-plane scenario `config.sh` scripts recreate the `llb1`
  container. For those scenarios, re-run step 3 (cert install + TLS restart) afterwards, or
  pass `--extra-args "--tls"` where supported. In the non-keepalived branch, if the scenario
  dir has a `cert/` folder, `common.sh` bind-mounts it over `/opt/loxilb/cert/` — install the
  monitoring certs into that host dir instead of `docker cp`. The `--with-ka` branch does not
  add this mount, so verify certificate placement separately.
- **Name your LB rules** (`loxicmd create lb ... --name=<svc>`): unnamed conntrack entries use
  `ServiceName="-"`, which the Prometheus exporter normalizes to an empty metrics key; named
  `service` attribution is therefore unavailable for those entries.
- **Verify endpoint probes** for health metrics/alerts: `--monitor` activates a derived
  protocol-appropriate probe. When the deployment needs an explicit probe type/port, use
  `loxicmd create endpoint <ip> --name=<ip>_tcp_<port> --probetype=tcp
  --probeport=<port> --period=10 --retries=2`.
